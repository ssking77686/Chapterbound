# 图鉴 JSON 编写规范

为电子阅读器生成图鉴数据时需要遵循的标准格式。阅读器通过 epub.js 的 spine index 自动检测当前章节，翻到对应章节后自动解锁该章节的发现条目。

---

## 一、顶层结构

```json
{
  "bookId": "",
  "characters": [],
  "locations": [],
  "monsters": []
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `bookId` | `string` | 是 | 书籍标识，与导入的 EPUB 文件名一致（不含扩展名），也可留空 |
| `characters` | `object[]` | 是 | 角色列表，至少 1 条 |
| `locations` | `object[]` | 是 | 地点列表，至少 1 条 |
| `monsters` | `object[]` | 是 | 怪物/生物列表，可空数组 |

---

## 二、条目通用字段

`characters`、`locations`、`monsters` 三个数组中的每个元素都遵循相同结构：

```json
{
  "id": "elara",
  "name": "艾拉·逐日者",
  "aliases": ["逐日者", "炎之剑"],
  "image": "",
  "category": "character",
  "description": "火之都最令人敬畏的佣兵剑士，一头赤红短发……",
  "entries": [
    { "chapter": 1, "text": "艾拉在火之都的竞技场中首次登场……" },
    { "chapter": 3, "text": "在霜脊山脉的遭遇战中，艾拉展现了她的真正实力……" }
  ],
  "relations": [
    { "targetId": "kael", "label": "宿敌" },
    { "targetId": "miranda", "label": "导师" }
  ],
  "quotations": [
    {
      "text": "艾拉？我第一次见她时她刚把三个佣兵扔出窗外。从那天起我就知道——这人能成大事。",
      "attribution": "——《佣兵列传》第三章"
    }
  ]
}
```

### 2.1 `id` — 唯一标识

- **类型**：`string`
- **规则**：仅使用英文小写字母、数字和下划线，如 `elara`、`frost_spire`
- **作用**：被 `relations[].targetId` 引用，必须全局唯一（角色、地点与怪物之间也不能重复）

### 2.2 `name` — 显示名称

- **类型**：`string`
- **规则**：完整中文名/原文名，如 `"艾拉·逐日者"`、`"霜脊山脉"`
- **注**：在详情页以大号字体展示

### 2.3 `aliases` — 别名列表

- **类型**：`string[]`
- **规则**：该角色的常用别名/绰号/简称
- **示例**：`["逐日者", "炎之剑"]`，`["老法师", "塔之主"]`
- **注**：在详情页以胶囊标签形式横向展示

### 2.4 `image` — 图片

- **类型**：`string`（可选）
- **格式**：base64 编码的图片数据（`data:image/png;base64,...`）或留空 `""`
- **注**：v1 阶段图片非必填，留空则显示默认占位图标

### 2.5 `category` — 分类

- **类型**：`"character" | "location" | "monster"`
- **规则**：角色填 `"character"`，地点填 `"location"`，怪物/生物填 `"monster"`

### 2.6 `description` — 基础描述

- **类型**：`string`
- **规则**：3-5 句话概括该角色/地点/怪物的核心设定，始终可见（不受章节解锁限制）
- **写法**：选择一个适合本书风格的叙述口吻（见第五节），统一应用到所有条目
- **示例**：
  > "艾拉·逐日者——佣兵行会的传奇。一头赤红短发，腰间那把炎之剑据说是她师父留下的唯一遗物。她接的委托从没失手过，但她要的报酬往往不是金币——而是情报。"

### 2.7 `entries` — 按章节分层的发现日志

- **类型**：`{ chapter: number; text: string }[]`
- **规则**：
  - `chapter` 是章节编号，从 **1** 开始递增
  - `text` 是当读者到达该章节时自动解锁的发现内容，2-4 句话
  - **同一章可有多条** entry，每条独立解锁
  - `entries` 按章节号从小到大排序
  - 该角色/地点/怪物首次出现的章节必须有至少一条 entry
  - **避免剧透**：每条 entry 只写该章节内读者能自然获知的信息

### 2.8 `relations` — 关联关系

- **类型**：`{ targetId: string; label: string }[]`
- **规则**：
  - `targetId` 引用另一个条目的 `id`
  - `label` 描述关系，3-6 字为佳
  - 关系是双向的：如果 A 的 relations 含 B，B 的 relations 也应含 A
- **常见关系标签**：
  - 人物→人物：`恋人` `导师` `宿敌` `挚友` `养父/养母` `兄弟` `仇敌` `君主` `部下`
  - 人物→地点：`家园` `首次登场` `关键事件地` `出生地`
  - 人物→怪物：`猎杀者` `宿敌` `首次遭遇`
  - 怪物→地点：`出没地` `巢穴`

### 2.9 `quotations` — 文献引述

- **类型**：`{ text: string; attribution: string; chapter?: number }[]`
- **规则**：
  - `text` 引用原文或虚构文献，一段话或几句对话
  - `attribution` 注明出处，如 `"——《佣兵列传》第三章"`
  - `chapter` 可选——填了则跟随该章节自动解锁，不填则始终可见
  - 建议每条条目引用 1-3 条文献
- **写作要点**：
  - 不同文献来源使用不同语气——学者的理性、诗人的抒情、猎人的实用
  - 视角互补——让每条引述揭示不同的侧面
  - 文献名称要有世界感但不必过度设计

## 三、章节编号规则

章节编号是**书籍 TOC（目录）中条目的顺序**，从 1 开始。与 epub.js spine index 自动映射。

### 如何确定章节号

1. 从 EPUB 中提取目录（TOC），按顺序列出所有章节
2. 第一章 = 1，第二章 = 2，以此类推
3. 序章/前言/楔子等也算一个章节号
4. 出版商信息/版权页等非正文内容通常不计入

### 重要约束

- `chapter` 的值不能超过书籍总章数
- 同一条目下的 entries 应按 `chapter` 升序排列
- 不必每章都写，但主要角色建议每章都有至少一条 entry

## 四、角色 / 地点 / 怪物的区分

### 角色（character）

- 有台词、有行动、推动情节的人物
- 重要配角也应包含

### 地点（location）

- 故事发生的重要场所
- 城市、王国、建筑、自然地貌均可

### 怪物（monster）

- 故事中出现的非人生物、怪兽、超自然存在
- 包括猎杀目标、神话生物、诅咒造物
- **注意**：如果某个怪物具有人格和重要剧情，应同时作为角色和怪物各建一条，角色的 description 侧重其人格，怪物的 description 侧重其物种特征

---

## 五、写作风格

图鉴文字需要在两种语域之间灵活切换：**画面感**与**书面感**。

### 5.1 两种语域

| 语域 | 适用场景 | 特征 |
|------|----------|------|
| **画面感** | 人物性格、关键事件、情感冲突、怪物遭遇 | 生动比喻、感官细节、个人态度 |
| **书面感** | 基础身份、地理信息、物种分类 | 简洁、客观、信息密度高 |

**核心原则：先立骨架，再添血肉。** 用书面笔法把事实交代清楚，再用画面感让读者记住它。

### 5.2 叙述者口吻

建议为图鉴选择一个与书籍风格一致的"叙述者"。例如：

- **旁观者视角**：像一位见多识广的旅人，认识书中人物，有主观评价，偶尔调侃
- **编年史视角**：像一本正经的百科编纂者，客观、信息密度高
- **书信/日记视角**：像书中某个次要角色的私人记录，亲切、私密

选择一种视角后，**整份 JSON 中的所有文字必须保持同一种口吻**。不能第一章旅人闲聊、第三章变成冷漠百科。

### 5.3 `description` 写法

- **长度**：3-5 句话
- **内容**：核心身份 + 最鲜明的特征 + 一句个人评价或趣事

### 5.4 `entries[].text` 写法

- **长度**：2-4 句话
- **内容**：该角色/地点在本章的关键事件 + 叙述者的观察
- **章章不同**：每章的 entry 揭示新的侧面，而非重复基本信息

### 5.5 好例子 vs 坏例子

| 好 | 坏 |
|----|-----|
| "你能想象吗？艾拉独自站在竞技场中央，赤红的短发在夕阳下像燃烧的火苗。她拔出炎之剑，剑刃泛着暗金光泽——那是她师父留下的唯一遗物。" | "艾拉在竞技场中首次登场，使用炎之剑战斗。" |
| "霜脊山脉的主峰终年积雪，山腰以下却是浓密的黑松林。据说龙巢就藏在最高那座山峰的北面——至少商队的向导是这么说的。" | "霜脊山脉是一个山脉，有龙巢。" |
| "老法师梅林的学生遍布七国，但真正让他骄傲的只有两个——一个成了国王的首席顾问，另一个烧掉了半座图书馆。" | "梅林是一位老法师，有两个学生。" |
| 无剧透：写第 3 章时只写到读者此时已知的信息 | 在第 1 章就写出角色在第 10 章才揭露的身份 |

### 5.6 怪物条目的特殊写法

- **夸张危险**：渲染怪物的威胁程度，让读者感受到压迫感
- **外貌细节**：具体且有画面感的外形描述
- **应对知识**：融入一些对抗方法或民间传说

**示例**：
> 火翼蜥——光这个名字就能让商队绕道走。成年火翼蜥翼展可达六米，鳞片是暗红色的，像冷却前的岩浆。它的尾巴能一击抽断马腿，嘴里喷出的不是火——是腐蚀性酸液。猎人们说，唯一的弱点是它腹部那块白色的软鳞，但要靠近到那个距离，你首先得躲过它的尾巴和酸液。

### 5.7 口吻一致性

同一份 JSON 中的所有文字（所有条目、所有章节）必须保持**同一种叙述口吻**。整份图鉴读起来应该像同一个人写的一本私人笔记或一部百科全书。

## 七、快速检查清单

生成 JSON 后逐项确认：

- [ ] `id` 全部唯一，仅含英文小写字母、数字、下划线
- [ ] `name` 使用完整中文名/原文名
- [ ] `category` 正确填写
- [ ] `description` 3-5 句话，无剧透
- [ ] `entries` 按 `chapter` 升序排列
- [ ] 每条 entry 的 `chapter` 值不超过书籍总章数
- [ ] 每条 entry 的 `text` 仅包含读者到该章为止自然获知的信息
- [ ] `relations` 双向引用一致（A→B 则 B→A）
- [ ] `relations[].targetId` 引用的 id 在 JSON 中存在
- [ ] 所有文字保持统一的叙述口吻
- [ ] JSON 语法合法（无尾逗号、引号闭合、花括号匹配）
- [ ] `bookId` 已填写或留空 `""`

## 八、使用流程

1. 从 EPUB 中提取完整 TOC（目录），确定各章节标题和编号
2. 将 TOC + 本规范一起交给 AI 助手
3. AI 根据其对书籍的了解生成 JSON
4. 在阅读器中打开书籍 → 侧栏"图鉴" tab → "导入 JSON" → 选择生成的 JSON 文件
5. **翻页阅读** → 图鉴按钮出现金色提示点 → 新解锁的人物/地点/怪物已出现在列表中
6. 点击条目查看详情 → 发现日志中该章节内容已解锁 → 未到达的章节内容模糊显示

## 九、随读随现机制

图鉴条目**不会在导入后立即全部显示**。只有当你翻页到达相关章节后，对应条目才会从列表中"浮现"。

### 触发条件

一条图鉴条目出现在列表中，需要满足以下任一条件：

- 该条目至少有一条 `entries[].chapter` ≤ 当前已读到的最大章节号
- 该条目至少有一条带 `chapter` 的 `quotations` ≤ 当前已读到的最大章节号

### 设计目的

防止剧透。如果你导入了一份覆盖全书 40 章的完整 JSON，你不会在第 1 章就看到第 35 章才出场的关键角色——他们会在你读到第 35 章时才从列表中浮现。
